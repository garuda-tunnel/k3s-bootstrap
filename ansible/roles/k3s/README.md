# Role `k3s`

Installs the pinned k3s for one node type with a module-owned unit and
`/etc/rancher/k3s/config.yaml`, starts it within `readiness_timeout` and
writes the completion marker `/var/lib/k3s-bootstrap/installed` (the node
type) last. `initial` gets `cluster-init`; `server` and `agent` join through
the head.

## Invariants

- Join (`tasks/join_server.yml`, `tasks/join_agent.yml`), while the marker
  is absent or k3s is gone: a server reads the head's server token into play
  memory; an agent gets a bootstrap token minted on the head with a TTL of
  `readiness_timeout` + 5 minutes, deleted by id in the role's `always` when
  the run ends, joined or not. Both land in `/etc/rancher/k3s/join-token`
  (0600 root). Every task that holds a token has `no_log` and no diff.
- The k3s token of an `initial` node is generated by k3s and never read.
- The installer runs only when the pin differs, with enable and start
  skipped and its units written outside systemd's search path, so the
  module's unit is the only one.
- Servers: `tls-san` always contains `127.0.0.1`; the kubeconfig is `0640`,
  group `ssh_user`'s primary group, in a `0710` directory (`config.yaml`
  stays `0600 root`). An agent's directory is `0700 root`.
- `config.yaml` and the unit are module-owned and rendered on every
  converge, replacing manual edits; operator settings belong in
  `config.yaml.d/` and unit drop-ins, which the role never writes (README,
  operator duties).
- The service is reconciled from host state alone, with no handler: an
  inactive unit is started; an active one is restarted when the config, a
  `config.yaml.d` fragment, the unit, the binary or the join token file was
  modified after the running process started (so a restart lost to an
  interrupted run is repeated by the next one). A restart is verified by a
  new InvocationID. The wait stops at a wall-clock deadline and fails with
  the journal tail.
- Skipped inside Docker containers (AGENTS.md, documented exception).

## Dependencies

Reads `preflight_k3s_installed_class`, `preflight_installed_marker` and
`preflight_k3s_installed_version` from the preflight play, the
`inventory_*` connection facts from `hostvars['localhost']`, and
`k3s_marker_path` from `ansible/group_vars/all.yml`. Delegated head tasks
connect as `head.user`.

## Variables

Inputs, types and allowed values: `meta/argument_specs.yml`, checked by Ansible on role entry; render with `ansible-doc -t role -r ansible/roles k3s`.
